# Crow-DLSS5-Video-Image-Converter V0.4.0

## New: complete offline video converter

V0.4.0 adds a dedicated Windows application:

- `Crow-DLSS5-Video-Image-Converter-Video.exe`

The image application and CLI remain available unchanged:

- `Crow-DLSS5-Video-Image-Converter-Image.exe`
- `Crow-DLSS5-Video-Image-Converter-CLI.exe`

## Video pipeline

The video converter uses a streaming pipeline rather than an image-sequence workflow:

1. ffprobe reads source width, height, frame rate, duration and audio presence.
2. FFmpeg decoder writes full-resolution RGBA8 frames to a pipe.
3. The existing D3D12 / DLSSNR Feature 18 path processes each frame.
4. Optional Depth Anything V2 guidance is generated by one persistent ONNX process.
5. The processed RGBA8 frame is written immediately to the FFmpeg encoder pipe.
6. Original-source audio is mapped into the output and encoded as AAC.

No PNG/JPEG intermediate frame sequence is written to disk.

## Realtime conversion preview

The video UI contains three live preview panes:

- ORIGINAL - LIVE
- DLSS5 - LIVE
- DEPTH GUIDANCE - LIVE

Preview refresh is intentionally limited to approximately 10 Hz so the UI does not become the main processing bottleneck. The conversion path still processes every source frame.

## Progress and ETA

The GUI reports:

- percentage
- current frame / estimated total frames
- processing FPS
- elapsed time
- ETA
- Preparing / Processing / Finalizing / Completed / Cancelled state

If the container reports `nb_frames`, it is used directly. Otherwise total frames are estimated from `duration * fps`.

## DLSSNR lifetime fix for video

V0.3.x recreated the D3D12 input/output/depth/motion resources and called Feature 18 CreateFeature for every `Process()` call. That was acceptable for single-image processing but not for a video stream.

V0.4.0 now caches, for a fixed resolution:

- Color texture
- Output texture
- Motion-vector texture
- Depth texture
- DLSSNR Feature 18 handle

Zero motion is uploaded once. Zero depth is also uploaded once when no external/auto depth is used. Per-frame work is therefore primarily Color upload, optional Depth upload, Evaluate, and readback.

Because this offline video path does not yet provide calibrated motion vectors, the first DLSSNR evaluation of every new source frame uses `Reset=true`. Additional iterations of that same frame may use `Reset=false`. This intentionally avoids temporal ghosting caused by retaining history without valid motion vectors.

## Auto Depth video server

`auto_depth_video.py` is a persistent binary-pipe server. It loads Depth Anything V2 / ONNX Runtime once, then accepts RGBA frames and returns normalized float depth frames without restarting Python for every video frame.

## FFmpeg dependency behavior

The program searches in this order:

- `dist/video/ffmpeg/bin/ffmpeg.exe`
- `dist/video/ffmpeg.exe`
- `dist/ffmpeg/bin/ffmpeg.exe`
- `dist/ffmpeg.exe`
- Windows PATH

`dist/video/setup_video.ps1` first checks an existing manual installation. If a local `ffmpeg-release-essentials.zip` exists in `dist/video`, it uses that archive. Otherwise it downloads the Gyan Release Essentials ZIP, preferring `curl.exe` and falling back to `Invoke-WebRequest`.

## Output codecs

The initial GUI exposes:

- H.264 NVENC
- HEVC NVENC
- H.264 CPU / libx264

The quality field maps to NVENC CQ or x264 CRF style values; lower values generally mean higher quality.

## Current contract

Video processing intentionally uses the already validated SDR RGBA8 Feature 18 contract. Native HDR / scene-linear FP16 video is not claimed by V0.4.0.
